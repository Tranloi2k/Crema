## Data model (Drizzle + Turso)
- `users`, `accounts`, `sessions`, `verification_tokens` — standard Auth.js Drizzle adapter tables.
- `templates`: `id`, `userId`, `name`, `content` (JSON-stringified `Block[]`), `createdAt`, `updatedAt`.

## Editor state (Zustand) — `editorStore.ts`
- `blocks: Block[]`, `selectedBlockId: string | null`
- actions: `addBlock(type, index)`, `removeBlock(id)`, `updateBlock(id, partial)`, `reorderBlocks(activeId, overId)`, `selectBlock(id)`, `setBlocks` (for load), plus `templateId`/`name`/dirty flag for autosave.
- `Block` shape: `{ id, type: 'text'|'image'|'button'|'divider'|'spacer', content: {...}, style: {...} }` — fields vary per type (e.g. text: `html` from TipTap; image: `src, alt, width, link`; button: `label, href, bgColor, textColor, borderRadius`; divider: `color, thickness`; spacer: `height`).

## Drag & drop (@dnd-kit)
- `BlockPalette` items are draggable sources (5 static cards); `Canvas` is a `SortableContext` over `blocks`. Dropping a palette item inside the canvas calls `addBlock`; reordering existing blocks calls `reorderBlocks`. Use `DndContext` at the page level wrapping both palette and canvas.

## Text block (TipTap)
- Minimal toolbar: bold, italic, link, alignment. Stored as HTML string in `block.content.html`, synced into the store on every edit (debounced) so Canvas/Preview re-render live.

## Properties panel
- Tabs (shadcn `Tabs`): "Content" and "Style" per selected block, fields driven by block type (text alignment/padding/color, image src/alt/width/link, button label/link/colors/radius, divider color/thickness, spacer height). No selection → empty state.

## Preview
- Reuses the same `BlockRenderer` + `toHtml()` output rendered in a sandboxed `iframe` (srcDoc) inside `PreviewModal`, so what's previewed matches the export exactly.

## Export (`lib/export/toHtml.ts`)
- Pure function `blocksToHtml(blocks: Block[]): string` producing a `<table role="presentation" width="600">`-based layout, all styles inlined per cell (no external `<style>` blocks), VML/MSO-safe basics (e.g. button as table-cell with bgcolor, not `<button>`). Exposed via a "Export HTML" toolbar action that downloads a `.html` file (`Blob` + anchor) — no server round-trip needed for export itself.

## Persistence / autosave
- `editorStore` exposes `dirty`; a `useAutosave` hook in the editor page debounces (~1.5s) and calls `PATCH /api/templates/[id]` with the serialized `blocks`. New templates are created via `POST /api/templates` (redirects into `/editor/[id]`) from the dashboard "New Template" button.
- `/dashboard` lists templates (name, updatedAt, thumbnail-less card for MVP) with create/delete/rename (shadcn `Dialog`).

## Auth
